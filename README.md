# بصيرة · استوديو اللقاءات (basserh-live)

منظومة إدارة اللقاءات ولحظات التدشين، تُؤجَّر لجهات متعددة. كل جهة تبني لقاءاتها من المتصفح (فقرات، أشخاص، عروض، مقاطع، هوية)،
تجري البروفة، تعتمد، ثم تفعّل يوم اللقاء فتفتح شاشات القاعة. هذا المجلد مكتفٍ بذاته، ومعدّ ليكون مستودعاً مستقلاً.

## البنية
    worker/     الخادم: index.js (الواجهة البرمجية)، tenant.js (قاعدة كل جهة)، room.js (غرفة كل لقاء)
    web/        الصفحات: index.html الاستوديو، admin.html مالك المنصة، run/ شاشات اللقاء، engine/ المحرّك، brand/ شعار بصيرة
    docs/STATIONS.md  المحطات التفاعلية: نوع لقاء ثانٍ (شاشات لمس، لكل شاشة ملف PDF)، وتصور قياس التصفح
    db/         control.sql: قاعدة التحكم فقط (الجهات، الأشخاص، العضويات، الجلسات)
    tenants/    مجلد لكل جهة تُزرع من ملف: tenant.json (من هي وبماذا تبدأ) ووثائق لقاءاتها. لا ملفات كبيرة هنا
    tools/      seed_tenant.mjs يزرع جهة من مجلدها عبر الواجهة البرمجية نفسها
    test/       engine.test.mjs (المحرّك)، e2e.cjs (المسار كاملاً، 24 فحصاً)، audience.cjs (صفحة الحضور: البرنامج والسؤال وما لا يُكشف لها، 14 فحصاً)، isolation.cjs (ثلاث جهات تعمل معاً، ومحاولات الدخول من الأبواب الخاطئة، ومفتاح تشغيل الشاشات، 20 فحصاً)، journey.cjs (رحلة جهة جديدة: إنشاؤها بكلمة مرور وبطاقة دخول، الدخول، تغيير كلمة المرور وتجديدها، القوالب والتراجع والنسخ وتعارض التعديل، الهوية من موقع والخط، 35 فحصاً)، screens.cjs (الشاشات بكل مقاس، شاشة الشعار الثابتة، أنماط التدشين، مقلّب المتحدث، التجهيز قبل يوم اللقاء، بثّ اللوحة ورسائل مدير الجلسة، 31 فحصاً)، closure.cjs (الأعضاء والسجل والتصدير والنسخ الاحتياطي وحذف الجهة، 20 فحصاً)، tenant_check.cjs (جهة مزروعة)، stations.cjs (المحطات التفاعلية: التفعيل للجهة، النوع، الرفع، شاشة المحطة المقفلة، اللوحة، الجوال، رمز الربط، رابط القاعة، المكتبة، 47 فحصاً)
    profile/    الملف التعريفي (بهوية بصيرة، وبلا شعار للبائع)

## العزل بين الجهات
* **الكود واحد للجميع، والجهة بيانات.** لا مجلد كود لكل جهة: مجلد `tenants/<slug>/` يحمل بيانات بدايتها فقط.
* **قاعدة بيانات لكل جهة:** لقاءات الجهة ونسخها المعتمدة وفهرس ملفاتها وروابط شاشاتها وسجلها في ملف SQLite خاص بها (Durable Object،
  `worker/tenant.js`)، يُنشأ آلياً عند إنشاء الجهة. لا يوجد جدول يجمع صفوف جهتين، فلا استعلام يصل إلى بيانات جهة أخرى.
* **قاعدة التحكم (D1):** من هي الجهات ومن هم الأشخاص وأدوارهم وجلسات دخولهم، ولا شيء من محتوى اللقاءات.
* **معرّف الجهة مكتوب في كل معرّف لقاء وكل رابط شاشة،** فيُعرف من الطلب نفسه أي قاعدة تُفتح، دون فهرس مشترك.
* **الملفات:** كل جهة في مجلدها داخل الحاوية (`<org>/<event>/...`)، ولا تُقرأ إلا بجلسة عضو في الجهة أو برابط شاشة من اللقاء نفسه.
* **الحالة الحية:** غرفة لكل لقاء، وأخرى لبروفته.

## التشغيل محلياً
    npm install
    npm run db && npm run dev
    npm run seed          # جهة الندوة ولقاؤها (MEDIA=مجلد الملفات الكبيرة)
    npm test && npm run test:e2e
لوحة مالك المنصة: `/admin.html` بمفتاح `ADMIN_KEY`. عنوان كل جهة: `/<slug>`.

## نموذج التأجير: يوم التفعيل
البناء والبروفة بلا مقابل؛ شاشات القاعة تفتح داخل نافذة التفعيل فقط (من مساء اليوم السابق حتى نهاية يوم اللقاء).
مالك المنصة يضيف للجهة أيام تفعيل، ومالك الجهة يفعّل اليوم الذي يختاره.

## أنواع اللقاءات
* **حفل تدشين:** فقرات متتابعة يقودها المشغّل.
* **المحطات التفاعلية:** شاشات لمس، لكل شاشة ملف PDF يتصفحه الزائر، ولوحة تعرض الشاشات وتبدّل ملفاتها. يفعّلها مالك المنصة لكل جهة من لوحته. التفاصيل في `docs/STATIONS.md`.

## النشر (منشور على https://live.basserh.com)
حساب Cloudflare الخاص ببصيرة: قاعدة التحكم D1 «basserh-live»، حاوية الملفات R2 «basserh-live-media»، الخادم «basserh-live» على النطاق live.basserh.com.
* الخادم: `npx wrangler deploy -c wrangler.live.toml` (بلا ملفات ثابتة). إن كان رمز الدخول بلا صلاحية R2 يرفض wrangler النشر، فيُرفع الناتج مباشرة:
  `npx wrangler deploy -c wrangler.live.toml --dry-run --outdir dist` ثم `PUT /accounts/<id>/workers/scripts/basserh-live` (metadata بالارتباطات الأربعة و index.js).
* الصفحات: `BASE=https://live.basserh.com ADMIN_KEY=... node tools/push_site.mjs` ترفع `web/` إلى الحاوية (`_site/`) عبر الخادم، وهو يقدّمها منها. تُعاد بعد أي تعديل في `web/`.
* جهة جديدة مجهّزة مسبقاً: `BASE=... ADMIN_KEY=... OWNER=... MEDIA=... node tools/seed_tenant.mjs tenants/<slug>`.
* التحقق بلا صرف يوم تفعيل: `node test/live_check.cjs <رابط دخول مالك> <اسم اللقاء>`.
* مفتاح مالك المنصة سرّ في Cloudflare (`ADMIN_KEY`)، وليس في المستودع.

## ما لم يُبنَ بعد
إرسال الدعوات بالبريد، تصدير بيانات جهة وحذفها عند انتهاء التعاقد، حذف ملفات الحاوية عند إزالة ملف، حدود على محاولات الدخول،
المعاينة الحية للشاشات داخل لوحة المشغّل، الشاشة الرأسية، اسم المتحدث أسفل الشاشة.

## بيئة التجربة وتعديلات قاعدة البيانات
* بيئة التجربة: `tools/staging.sh` ينشرها على `basserh-staging.<الحساب>.workers.dev` بقاعدة بيانات ومخزن ملفات وكلمة مرور إدارة خاصة بها. كل تعديل يُجرَّب هناك أولاً.
* تعديلات قاعدة التحكم ملفات مرقّمة في `db/migrations/`، تُطبَّق بالترتيب مرة واحدة: `node tools/migrate.mjs staging` ثم `node tools/migrate.mjs live`.
